## How the pass runs

- **One writer per file at a time.** The editor writes into an owner's generator only after that owner reports done, and tells the main session first. Never edit another owner's file.
- **Generator trap.** Chapter files and specimens are written by build scripts. A change made only to an output file is lost on the next run. Every fix goes into the generator or its data, then the generator runs, and its outputs are committed by the main session.
- **Prove each change.** Rerun your generator; build the page in your own scratch folder with `python3 -I work/build/scripts/phase-2/guide_build.py --strict --out <your scratch>/guide.html` (exit 0, 0 warnings); for a kit change, `node work/build/chart-kit/oa-chart.mjs build <spec> --out <scratch>/kit-out`; then `git diff --stat` shows only your files. Restore `work/build/chart-kit/plate-share.json` if the build rewrote only its timestamp (`git checkout -- work/build/chart-kit/plate-share.json` for that one file only, never a wider checkout). For a change whose reach goes past your plate, measure what moved and write it down.
- **Browsers (DR-277).** Run `bash /tmp/claude-0/-home-user-Dustin-s-Command-Center/f55a08bf-cdcf-539d-a683-426e26f4f342/scratchpad/c07/browsers.sh` before any browser and open one only when it prints "OK to open one". Never run the guide check; the main session runs it on the joined build.
- **Notes.** Write `work/handoffs/phase-3/20261116_Fix-Pass-<Owner>-Notes.md` (Data-Lead, Research, Editor, Systems-Designer, Complex-Examples, Tracker-Designer): "Fixed" (code, what changed, file, proof), "Not fixed" (code and the reason; a Should may be declined with a reason the data lead accepts), "Calls" (`| call | reason |` rows, unnumbered), "Requests", "Tested" and "Not tested". Start it within your first 20 minutes and add as you go; the container can restart.
- **Read each other's notes.** The data lead's "Rulings", the research lead's "Facts" and the editor's "Words for <owner>" sections are written for you to read directly, so the main session relays less.
- Read the clock with `date -u` before writing a time. Plain sentences, no em dashes, chapter 02's rules for every word a reader sees. Never touch `source/`, `work/ledger/`, `deliverables/`, any board or another owner's files. Do not commit or push. Never run `git checkout --` on anything but the one timestamp file above.
- Reply to the main session in 150 words or fewer when you finish: what you fixed, what you did not and why, and what waits on someone else.
