1. Every page rendered

    What it shows
    Each page draws whole at the widths readers use
    Method
    Screenshots at 1440, 1024, 390 and 360 px, looked at by a person
    Criteria
    1.4.10

  2. Report pages

    What it shows
    Every page of a report reads in the reader
    Method
    A screenshot of each page in the report reader
    Criteria
    1.4.10, 4.1.2

  3. Keyboard and focus

    What it shows
    Every control is reached in order, shows its ring, holds no trap and is big enough to press
    Method
    A script presses Tab through the page, walks each component’s keyboard path and measures each control’s size; a person checks the order and the ring
    Criteria
    2.1.1, 2.1.2, 2.4.3, 2.4.7, 2.4.11, 2.5.8
    To run it
    To list each control under 24 by 24 px, paste this into the browser’s console: document.querySelectorAll('a, button, input, select, summary, [tabindex]').forEach(el => { const r = el.getBoundingClientRect(); if (r.width && (r.width < 24 || r.height < 24)) console.log(el, Math.round(r.width), Math.round(r.height)); }). A link inside a sentence may be smaller.

  4. Reading order and headings

    What it shows
    The outline makes sense read aloud
    Method
    The accessibility tree’s outline, read by script and by a person
    Criteria
    1.3.1, 1.3.2, 2.4.6
    To run it
    In Chrome’s developer tools, open the Elements panel’s Accessibility pane and turn on the full-page accessibility tree.

  5. Forms and messages

    What it shows
    A reader can find and fix every field, then send the form
    Method
    Send each form empty, then with a mistake, by keyboard: focus lands on the first field to fix, its description holds the message, and the status line holds the result
    Criteria
    1.3.5, 3.3.1, 3.3.2, 3.3.3, 4.1.3

  6. Automated rules

    What it shows
    The faults a machine can find are gone
    Method
    axe-core with the tags wcag2a, wcag2aa, wcag21a, wcag21aa and wcag22aa on every page
    Criteria
    Parts of many, such as 1.1.1, 1.3.1, 1.4.3, 2.4.2, 2.4.4, 3.1.1 and 4.1.2
    To run it
    npx @axe-core/cli https://example.org/your-page --tags wcag2a,wcag2aa,wcag21a,wcag21aa,wcag22aa --exit, which needs Chrome and stops with an error when a rule fails.

  7. Contrast

    What it shows
    Text, marks, edges and focus rings stand out from their ground
    Method
    A script reads each rendered color pair, states included; a person measures marks, edges and rings against 3 to 1
    Criteria
    1.4.3, 1.4.11
    To run it
    For text: npx @axe-core/cli https://example.org/your-page --rules color-contrast. For marks and edges, a color picker and the ratios in chapter 26’s token table.

  8. Text at 200 percent and 320 px

    What it shows
    Nothing is cut off, lost or broken in the middle of a word when text grows, spacing opens or the screen narrows
    Method
    Text doubled, the page at 320 px, then line height 1.5, paragraph spacing 2 times the size, letter spacing 0.12 and word spacing 0.16 times the size, all at once. A script finds sideways scroll and clipped boxes, and a person reads for words broken in the middle
    Criteria
    1.4.4, 1.4.10, 1.4.12
    To run it
    To double the text, paste document.documentElement.style.fontSize = '200%' into the console; then document.documentElement.scrollWidth > innerWidth reads true where the page scrolls sideways. For the spacing, add * { line-height: 1.5 !important; letter-spacing: 0.12em !important; word-spacing: 0.16em !important } p { margin-bottom: 2em !important }.

  9. Reduced motion

    What it shows
    Nothing moves on its own, and every motion has a still end
    Method
    The browser set to reduce motion, then each moving part played
    Criteria
    2.2.2, 2.3.1
    To run it
    In Chrome’s developer tools, open Rendering and set “Emulate CSS media feature prefers-reduced-motion” to reduce.

  10. Forced colors

    What it shows
    Every mark, edge and state survives a contrast theme
    Method
    The browser set to forced colors, light and dark, then each part read by script and by eye
    Criteria
    1.4.1, 1.4.11
    To run it
    In Rendering, set “Emulate CSS media feature forced-colors” to active, with prefers-color-scheme set to light, then to dark.

  11. Dark surfaces and long labels

    What it shows
    Each part reads on every surface it uses, with the longest real words
    Method
    Each part on Newsprint, Charcoal and any other surface it uses, filled with the longest real words it will hold, such as the longest title in its data
    Criteria
    1.4.3, 1.4.10

  12. Print

    What it shows
    A printed page keeps its words and order
    Method
    Print emulation and the print stylesheet: every word prints, in reading order, and nothing is cut at a page’s edge
    Criteria
    1.3.2
    To run it
    In Rendering, set “Emulate CSS media type” to print.

  13. Downloads

    What it shows
    Each file arrives whole and named
    Method
    Press each download, open each file, check SVG validity and PNG size
    Criteria
    2.4.4

  14. Diagram and chart equivalents

    What it shows
    A reader who cannot see a drawing gets its connections
    Method
    Each drawing checked for its words or table and its reading guide
    Criteria
    1.1.1, 1.3.1

  15. Grayscale

    What it shows
    Nothing rests on color alone
    Method
    Grayscale screenshots of every page, with each state shown
    Criteria
    1.4.1
    To run it
    Paste document.documentElement.style.filter = 'grayscale(1)' into the console.
